# Nest & Nova — Simple E-commerce Store

A complete beginner-friendly e-commerce demo built with **Django (Python), HTML, CSS, JavaScript, and a database**. It is designed for local use and can be deployed on Render with a Neon PostgreSQL database.

## Included features

- Product listing, product details, product search, and category filtering
- Session-based shopping cart with quantity update and item removal
- User registration, login, and logout
- Checkout with delivery details and **Cash on Delivery demo mode**
- Order creation, order history, and order confirmation page
- Stock validation and stock decrement when an order is placed
- Django admin for managing products, inventory, and orders
- Eight sample products loaded by a repeat-safe management command
- Responsive layout for desktop and mobile screens
- SQLite for local development; PostgreSQL through `DATABASE_URL` in deployment

> **Important:** This is a learning/demo project. It does not connect to a payment gateway, send real emails, or provide a carrier integration. Checkout records an order and selects Cash on Delivery; do not treat it as a production store without a security, privacy, payment, and operational review.

## 1. Run locally on Windows

Install Python 3.11 or newer, then open PowerShell or a terminal in the folder containing `manage.py`.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py migrate
python manage.py seed_products
python manage.py createsuperuser
python manage.py runserver
```

Open **http://127.0.0.1:8000/**. The Django admin is at **http://127.0.0.1:8000/admin/**.

If PowerShell blocks virtual-environment activation, you can use Command Prompt and run `.venv\Scripts\activate.bat`. Alternatively, run commands with `.venv\Scripts\python.exe` explicitly.

The default local configuration uses SQLite, so it works without setting up a separate database. For local testing, the placeholder `SECRET_KEY` is acceptable only on your own machine.

## 2. Push the project to GitHub

1. Create a new, empty repository on GitHub.
2. In a terminal opened at the project root, run:

```bash
git init
git add .
git commit -m "Build Django e-commerce store"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Replace the example GitHub URL with your repository URL. Do **not** commit `.env`; it is ignored by `.gitignore`.

## 3. Create the PostgreSQL database on Neon

1. Sign in to [Neon](https://neon.tech/) and create a project.
2. In the Neon Console, choose **Connect** and copy the PostgreSQL connection string for your database and role.
3. Keep the string private. It contains database credentials. It should be entered into Render as an environment variable, not committed into your code.

A typical connection string begins with `postgresql://` and usually includes `sslmode=require`. Use Neon's current connection string; do not copy a sample password from documentation.

## 4. Deploy on Render

This repository includes `render.yaml` so Render can read the web-service configuration.

1. Sign in to [Render](https://render.com/) and choose **New → Blueprint** (or create a new Web Service if you prefer manual configuration).
2. Connect the GitHub repository you pushed in the previous step.
3. Review the `simple-ecommerce-store` service and apply/deploy the Blueprint.
4. In the Render service dashboard, open **Environment** and set `DATABASE_URL` to the Neon connection string from the previous section. The Blueprint deliberately marks this variable as a secret you provide. Keep `SECRET_KEY` generated by Render and keep `DEBUG=False`.
5. Wait for the build and deploy to finish. The included `build.sh` installs packages, collects static files, runs migrations, and loads the sample products.
6. Open the `onrender.com` URL shown in the Render dashboard.

### If you deploy manually instead of using the Blueprint

Create a Python Web Service connected to the repository and set:

- **Build command:** `bash build.sh`
- **Start command:** `gunicorn store.wsgi:application`

Set these environment variables in Render:

| Variable | Value |
|---|---|
| `SECRET_KEY` | Generate a private, random value in Render |
| `DEBUG` | `False` |
| `DATABASE_URL` | Your Neon PostgreSQL connection string |
| `PYTHON_VERSION` | `3.13.5` |

Render supplies `RENDER_EXTERNAL_HOSTNAME` automatically; the project uses it for `ALLOWED_HOSTS` and HTTPS CSRF trust.

## 5. Create an admin account on the deployed site

In the Render service dashboard, open **Shell** (if available for your service) and run:

```bash
python manage.py createsuperuser
```

Then visit `https://YOUR-RENDER-URL/admin/` and sign in. From the admin you can add products, update price and stock, deactivate products, and manage order statuses. If the free plan/dashboard does not provide a Shell, create the superuser locally **after temporarily pointing your local `.env` at the same Neon `DATABASE_URL`**, run the command, then restore your local configuration. Keep the database credentials private.
